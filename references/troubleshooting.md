# 故障排查手册

按"先判断通道，再判断对象，最后判断操作"的顺序排查。绝大多数失败不是任务难，而是输入没有真正送达。

---

## 一、判断输入通道是否还活着

在继续点任何东西之前，先做一次**最小可观测动作**：移动光标 + 截图，看光标位置是否变化。

| 观察结果 | 结论 |
|---|---|
| 光标动了，点击也有反馈 | 通道正常，问题在目标元素或坐标 |
| 光标动了，点击无反馈 | 点击落点不对，或目标窗口未激活 |
| 光标不动 | 通道被占用/被 grab，见 §2 |
| 截图是黑屏或纯色 | 目标屏幕被锁定/息屏，见 §3 |
| 完全连不上 | 服务端没起或被防火墙拦，见 §4 |

---

## 二、光标锁死（SetCursorPos 返回 0）

**典型特征**：`SetCursorPos` 返回值 0；`GetCursorPos` 永远同一个点；`mouse_event` 绝对坐标与相对位移都不生效；键盘也无反应。

原因只有两类：**有窗口 grab 了指针**，或**有模态对话框独占了输入队列**。

排查顺序：

1. 枚举该进程的顶层窗口，找标题可疑的对话框：
   - VMware：`可移动设备`、`客户机操作系统已禁用 CPU`、`此虚拟机似乎正在使用中`
   - 系统：UAC 提权框、`用户账户控制`
2. 关闭对话框：
   - 先 `PostMessage(hwnd, WM_CLOSE, 0, 0)`；
   - 关不掉就 `pywinauto.Application(backend="win32").connect(handle=hwnd)`，找按钮 `.click()`；
   - 再不行就重启该应用的界面进程。
3. VMware 特有解法：`Stop-Process -Name vmware`（只杀 UI）。虚拟机本身跑在 `vmware-vmx.exe` 里，**不会关机**；重新 `Start-Process vmware.exe`，在库列表里双击该虚拟机即可重新拿到画面。
4. 无效手段（别浪费时间）：切换前台窗口、`ClipCursor(NULL)`、反复 `ShowCursor(True)`、`SetForegroundWindow` 后重试。

**预防**：不要让虚拟机控制台长时间持有焦点；脚本化操作一律走 VNC 通道，不碰控制台。

## 三、截图黑屏 / 纯色 / 尺寸不对

| 现象 | 原因 | 处理 |
|---|---|---|
| 客户机内 `import` 得到 1-bit 纯黑图 | 屏幕已锁定或 DPMS 息屏 | 解锁；或关闭自动锁屏；或用 `xset s off -dpms` |
| 截图为纯色但 VNC 正常 | 同上，root 窗口被覆盖层遮住 | 以 VNC 为准，或先解锁再截 |
| 截图为纯色但 VNC 也纯色 | 客户机黑屏（显卡驱动/休眠） | 发一次键鼠唤醒，再截 |
| 主机抓 VMware 窗口全黑 | 硬件加速/遮挡 | 改用客户机内截图 |
| 只截到窗口一部分 | 用了旧的窗口 rect | 最大化后重新取 rect 再抓 |
| 图像缩放后坐标全偏 | 截图被压缩 | 用 原图/显示 比例换算 |

**判定技巧**：拿 `PIL` 打开截图，`im.mode == "1"` 或整幅只有一个颜色，就是没截到内容，不要继续用这张图做坐标分析。

## 四、VNC 连不上 / 握手失败

| 报错 | 原因 | 处理 |
|---|---|---|
| `ConnectionRefusedError` | VNC 没启用，或虚拟机没开 | 检查 vmx 三行配置；确认 VM 正在运行 |
| 读到 0/4 字节就 EOF | 服务端设了密码，客户端发了零密钥 | 客户端补密码；或服务端清空密码 |
| banner 不是 `RFB` | 端口被别的服务占用 | 换端口；`netstat -ano | findstr 591x` 查占用 |
| 认证失败（4 字节非 0） | 密码错；或密码超 8 位被截断 | 用 8 位以内密码 |
| 请求帧缓冲一直超时 | `SetEncodings` 的 count 与编码数不符；或像素格式报文残缺 | 删掉 SetEncodings，用默认格式 |
| 画面尺寸与客户机分辨率不一致 | 没申请 DesktopSize 伪编码 | 断开重连 |

排查顺序：`Test-NetConnection 127.0.0.1 -Port 5910` → 裸 socket 读 12 字节 banner → 再跑完整客户端。

## 五、VMware 虚拟机起不来 / 起不来桌面

### 5.1 掉进 initramfs（`(initramfs)` 提示符）

原因：硬关机或断电导致根分区脏，UUID 解析失败。

```
fsck -y /dev/sda1
exit
```

仍报 `No init found` 时，说明 initramfs 里没能把根挂上，手工接管：

```
mount /dev/sda1 /root
mount -t proc proc /root/proc
mount -t sysfs sys /root/sys
mount -o bind /dev /root/dev
exec chroot /root /sbin/init
```

进入系统后建议 `update-initramfs -u`，下次开机就不会再卡。

**预防**：优先 `vmrun stop <vmx> soft`（走 ACPI），不到万不得已不用 `hard`。

### 5.2 开机黑屏 + "客户机操作系统已禁用 CPU"

虚拟机内部发生了 triple fault（常见于被 DoS 打崩的实验靶机）。这是 VMware 的保护性提示，直接 `reset` 或 `stop hard` + `start` 即可，不影响磁盘。

### 5.3 客户机命令"执行了但没反应"

- GUI 程序缺 `DISPLAY` / `XAUTHORITY`，静默退出。补上环境变量。
- `runProgramInGuest` 对 GUI 程序立即返回，拿不到输出。让它重定向到文件再取回。
- 脚本没有执行权限也不影响（由 `/bin/bash script` 调用），但路径写错会静默失败，先 `ls` 确认文件到位。

## 六、点击类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 点了没反应，第二次才生效 | 首次点击仅激活窗口 | 先聚焦，或固定"点两次"，中间截图确认 |
| 点一下变成双击效果 | 发送了两次按下 | 修正为单次按下+释放 |
| 单选按钮点不动 | 点在圆圈边缘 | 点标签文字 |
| 拖拽无效 | 缺少中间移动帧 | 按下后分 8–15 步移动再抬起 |
| 下拉列表展开后点空 | 列表项位置随滚动变化 | 展开后重新截图取坐标 |
| 关闭按钮点不掉弹窗 | 弹窗有"最小化到托盘"行为 | 走 `WM_CLOSE` 或用快捷键 Esc |

## 七、键盘类问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 后续按键全变快捷键 | Ctrl/Alt/Shift 卡在按下状态 | 显式补发释放；或 `key up` 全部修饰键 |
| 中文打不出来 / 变成问号 | keysym 只支持 ASCII | 剪贴板粘贴 |
| 快捷键无效 | 目标窗口没焦点 | 先点击窗口内容区，再发快捷键 |
| 组合键顺序错乱 | 修饰键与字符键并发发送 | 修饰键按下后加 20–50ms 间隔 |
| 控制台方向键乱跳 | 光标不在命令提示符 | 先按一次 Esc 或点击提示符行 |

**修饰键卡住的急救**：依次发送 `ctrl up`、`alt up`、`shift up`、`win up`，再试一次轻量动作。

## 八、Windows 客户机专项

- **分辨率对话框**：改分辨率后 12 秒内必须点"保留更改"，否则自动回滚。脚本要一次连发"应用 → 保留"。
- **UAC 安全桌面**：能截到图，注入常失败。需要管理员权限时，直接以管理员身份启动目标程序，或改用 PowerShell 工具执行。
- **输入法**：中文输入法激活时，命令行里的字母会进候选窗。稳妥做法是先切英文（`Shift` 或 `Ctrl+Space`），或全程用剪贴板。
- **控制台代码页**：默认 936，跨终端传输出会乱码，`chcp 65001` 后重跑命令。
- **资源管理器列表**：单击选中、双击打开，误发双击会弹出属性框；选行请单击并截图确认。

## 九、Linux 客户机专项

- 桌面环境要分清：Kali 2024 默认 **qterminal**（不是 xfce4-terminal），窗口类名 `qterminal`；GNOME 系是 `gnome-terminal-server`。
- `xdotool` 是万金油：`search --class`、`windowsize`、`windowmove`、`getwindowgeometry`、`key`、`type`。
- `xrandr --output Virtual1 --mode WxH` 只在模式列表里存在时有效，先 `xrandr` 查。
- VMware 会按窗口大小自动改分辨率，改完立刻截图确认。
- qterminal 默认半透明，截图发灰；要干净图就改配置（`~/.config/qterminal.org/qterminal.ini`）或换 `xterm`。
- 锁屏是截图黑屏的头号原因，长实验前先关掉自动锁屏。

## 十、文件与进程锁

| 现象 | 处理 |
|---|---|
| 文档被占用，无法覆盖/删除 | 先关闭打开它的编辑器（`close_file`）、退出 Word/WPS、停掉相关进程 |
| 删除被安全策略拦截 | 用应用的"另存为"换名，或先移动到临时目录再处理 |
| 端口被占用 | `netstat -ano | findstr :端口` → `taskkill /PID` |
| 后台守护进程残留 | 按命令行特征筛选进程：`Get-CimInstance Win32_Process | Where CommandLine -like '*xxx*'` |

---

## 十一、收尾检查

- 关掉临时 VNC 端口、杀掉守护进程
- 把对系统做过的改动列清单（改了哪些配置文件、动了哪些目录、装了哪些包）
- 恢复为客户机准备的分辨率/锁屏设置
- 需要长期保留的截图单独归档，不留在临时目录
